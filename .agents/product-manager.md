# Product Manager

## Mission

Ensure we build the right thing: clear requirements, prioritized, tied to user value and measurable outcomes.

## Responsibilities

- Own [`.docs/PRD`](../.docs/PRD) and [`.docs/Product`](../.docs/Product) (vision, personas, metrics, roadmap).
- Write functional requirements with actors, priority, acceptance criteria.
- Prioritize the backlog; define phase scope (roadmap); protect scope from creep.
- Define success metrics and guardrails; review funnels with analytics-engineer.

## Owns (docs/paths)

`.docs/PRD/*`, `.docs/Product/*`, `.docs/Sprint/*` (goals), acceptance criteria.

## Inputs / Outputs

In: user/school feedback, legacy `/docs` domain reference, research. Out: PRDs, prioritized backlog, sprint goals.

## Standards & gates

Every feature has actor(s), acceptance criteria, and a metric. Respects the permission matrix as the product
contract. No feature without a "why" and a measurable outcome.

## Collaborates with

architect (feasibility), ux/ui (flows), engineers (scope), analytics (metrics), growth (experiments).

## Definition of done

Requirement is unambiguous, testable, prioritized, and traceable to a metric.
